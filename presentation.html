Passerelle JSM → Google Workspace · Admin
v3.2.0

Du ticket validé à l'action exécutée, sans intervention manuelle

Aujourd'hui, une demande d'administration Workspace (arrivée, départ, accès, mot de passe…) circule par e-mails, formulaires Google et scripts épars avant d'être exécutée à la main dans la console. La passerelle branche Jira Service Management directement sur l'Admin SDK : l'agent valide le ticket, l'action s'exécute, le ticket reçoit le compte rendu.

Aujourd'hui

Trois canaux parallèles, un fil conducteur inexistant

La même demande peut arriver par e-mail, par Google Forms ou déclencher un script isolé. Dans tous les cas, quelqu'un doit relire, ressaisir puis cliquer dans la console — et la trace se disperse entre boîtes mail, onglets Sheets et mémoire des admins.

  • trace dispersée (mails, onglets)
  • double saisie et fautes de frappe
  • statut invisible pour le demandeur
  • dépend de la disponibilité d'un admin
  • étapes oubliées sur les départs / arrivées
Avec la passerelle

Un seul flux, tracé de bout en bout

Le portail JSM devient le guichet unique. Quand l'agent valide le ticket, Jira Automation envoie un webhook à la passerelle Apps Script, qui contrôle, exécute via l'Admin SDK, journalise, puis revient commenter et résoudre le ticket. Personne ne ressaisit rien.

Ce que ça change

Quatre gains immédiats

Guichet unique

Une seule porte d'entrée : le portail JSM. Plus de demandes en fil de mail, de Forms orphelins ni de scripts à lancer soi-même.

Zéro ressaisie

Les champs du formulaire JSM partent tels quels dans le webhook. Ce que le demandeur saisit est ce que l'Admin SDK exécute.

Traçabilité complète

Chaque opération est liée à un ticket, horodatée dans le journal d'audit et commentée en retour sur le ticket. Qui, quoi, quand : toujours retrouvable.

Délai en minutes

L'exécution suit la validation de l'agent, sans attendre qu'un admin soit disponible pour cliquer dans la console.

Au-delà du déclenchement

Ce que la passerelle apporte en plus des scripts actuels

Sécurité encadrée

Secret partagé sur le webhook, validation stricte des données, confirmation obligatoire pour les suppressions, et erreurs typées renvoyées lisiblement à l'agent JSM.

Créneaux et file d'attente

Les actions sensibles ne s'exécutent que dans les fenêtres d'administration (jours fériés compris). Hors créneau, la demande est mise en file et rejouée automatiquement — le ticket est prévenu.

Orchestrations métier

Des séquences complètes en un ticket : ARRIVEE_COLLABORATEUR, DEPART_COLLABORATEUR, MUTATION_INTERNE, URGENCE_COMPROMISSION… chaque étape dans le bon ordre, sans oubli.

Un catalogue, pas des scripts épars

49 actions déclarées dans un registre unique, avec les mêmes contrôles, le même journal et le même retour Jira — au lieu de scripts isolés à maintenir un par un.
