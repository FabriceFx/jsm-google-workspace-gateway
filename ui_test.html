settings_ethernet 1. Architecture de connexion Jira Automation

Pour chaque formulaire JSM (Création de compte, Demande d'accès, Départ, Réinitialisation de mot de passe...), l'intégrateur doit créer une règle dans Jira Automation (Paramètres du projet > Automation > Create Rule).

1. Déclencheur (Trigger)

Issue Transition (ex: passage à "En cours" ou "Approuvé") ou Component / Issue Created.

2. Action Webhook

Ajouter une action "Send web request" configurée en POST.

3. Webhook URL

L'URL de déploiement de cette WebApp (ex: https://script.google.com/macros/s/.../exec).

4. Content-Type

Régler l'en-tête HTTP sur application/json.

code 2. Structure standard du Payload JSON Jira

Chaque requête envoyée par Jira Automation doit respecter le schéma JSON canonique suivant : 

{
  "secret_token": "VOTRE_SECRET_TOKEN_PROPERTIES",
  "action": "NOM_DE_L_ACTION",
  "ticket_key": "{{issue.key}}",
  "request_id": "{{issue.key}}-{{now.epochMillis}}",
  "data": {
    "champ_1": "{{issue.customfield_10001}}",
    "champ_2": "{{issue.customfield_10002}}"
  }
}

call_split 3. Traitement des réponses dans Jira Automation

Après l'action Send web request, ajoutez des conditions basées sur {{webResponse.status}} :

Statut 200 (Succès immédiat)

L'action a été exécutée sur Google Workspace. Ajouter un commentaire public sur le ticket : {{webResponse.body.message}} et passer le ticket à "Résolu".

Statut 202 (Mis en file d'attente)

Demande effectuée hors créneau d'administration. Ajouter un commentaire d'information : "Demande enregistrée pour exécution automatique au prochain créneau ({{webResponse.body.scheduled_for}})."

Statut 400 / 403 / 404 / 500 (Erreur)

Une anomalie a empêché l'exécution. Ajouter un commentaire interne d'erreur : {{webResponse.body.message}} et assigner le ticket au support N2.
